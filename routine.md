# Рутина: меню недели Наташе

Инструкция облачному агенту. Задача одна: в воскресенье отправить Наташе в Telegram
одно сообщение со ссылкой на меню будущей недели.

**Главное правило: рутина ничего не считает и не сочиняет.** Меню раскладывает сама
страница. Рутина только считает даты, проверяет, что страница жива, и отправляет ссылку.
Ни рецептов, ни списка продуктов в сообщение не вставлять.

---

## Что нужно в окружении

Задаётся в настройках cloud environment (claude.ai/code → окружение → Environment variables).

| Переменная | Что это |
|---|---|
| `MENU_BOT_TOKEN` | токен бота @Racionpitaniadeltsovybot |
| `NATASHA_CHAT_ID` | чат Наташи — основной получатель, `932962811` |
| `ADMIN_CHAT_ID` | чат Кости — туда уходят только сообщения о сбоях |

Если `ADMIN_CHAT_ID` не задана — сообщение о сбое никуда не отправлять,
просто записать ошибку в лог рутины и остановиться. Наташе про сбои не писать.

**Network access** окружения должен быть `Custom` со включённым списком по умолчанию плюс
два домена: `api.telegram.org` (куда уходит сообщение) и `ubermag96-bit.github.io`
(страница меню, её проверяем перед отправкой). Без этого запросы молча не уйдут.

Расписание: cron `0 9 * * 0` в UTC — это воскресенье 14:00 по Екатеринбургу.
Таймзону в рутинах задать нельзя, только UTC.

## Шаг 1. Посчитать даты

Рутина просыпается в воскресенье, меню — на следующие семь дней, с понедельника
по воскресенье.

```bash
D1=$(date -u -d 'tomorrow' +%-d)
M1=$(date -u -d 'tomorrow' +%m)
D2=$(date -u -d '7 days' +%-d)
M2=$(date -u -d '7 days' +%m)
```

Номер месяца превратить в название родительным падежом: 01 января, 02 февраля,
03 марта, 04 апреля, 05 мая, 06 июня, 07 июля, 08 августа, 09 сентября,
10 октября, 11 ноября, 12 декабря.

Если месяц один и тот же — писать его один раз: «15 — 21 сентября».
Если разные — оба: «29 сентября — 5 октября».

## Шаг 2. Проверить, что страница жива

```bash
CODE=$(curl -sS -o /dev/null -w '%{http_code}' https://ubermag96-bit.github.io/natasha-menu/)
```

Если код не `200` — Наташе **не писать**. Отправить в `ADMIN_CHAT_ID`:

```
⚠️ Меню не отправлено: страница отвечает <код>
```

и на этом остановиться.

## Шаг 3. Отправить

Текст ровно такой, только даты подставляются:

```
🍽 Меню на неделю <даты>

На каждый завтрак, обед и ужин — три варианта. Выбери, что нравится,
и внизу соберётся список продуктов на всю неделю.

https://ubermag96-bit.github.io/natasha-menu/
```

```bash
curl -sS -X POST "https://api.telegram.org/bot$MENU_BOT_TOKEN/sendMessage" \
  -d chat_id="$NATASHA_CHAT_ID" \
  -d disable_web_page_preview=false \
  --data-urlencode text@/tmp/msg.txt
```

Ответ Telegram должен содержать `"ok":true`. Если нет — повторить один раз, затем
сообщить о сбое в `ADMIN_CHAT_ID` и записать ошибку в лог рутины.

## Если сломалось

Молчание хуже ошибки: если Наташе сообщение не ушло, Костя должен об этом узнать.
Поэтому любая неудача заканчивается сообщением в `ADMIN_CHAT_ID`.

Что бывает:

- `"ok":false` с `chat not found` — Наташа ещё не нажала «Начать» в боте либо
  в `NATASHA_CHAT_ID` не тот номер;
- `"ok":false` с `bot was blocked by the user` — она заблокировала бота, писать бесполезно;
- пустой ответ или таймаут — домен не в списке разрешённых в Network access;
- код страницы `404` — GitHub Pages не собрался или репозиторий переименован.

## Чего не делать

- Не пересказывать меню и не перечислять блюда в сообщении — их показывает страница.
- Не менять текст сообщения от запуска к запуску, не добавлять пожелания и смайлики
  сверх тех, что в шаблоне.
- Не отправлять второе сообщение при повторном запуске в тот же день.
- Не трогать файлы репозитория: рутина только читает.
